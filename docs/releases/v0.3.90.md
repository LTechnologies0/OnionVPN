## Highlights

Critical **audit-round-1 B10 fixes** — fail-closed TProxy JNI, kotlin-tor hard-brick prevention, LocalSocket readiness, password-on-disk removal, /proc budget, RFC1918 UDP reject, SecurityException fallback, ownership serialization. Plus CI wiring for kotlin-tor composite engine.

## Critical Fixes (B10 / CRITICAL)

- **TProxy JNI fail-closed**: `TProxyService` init now logs and records error if either native library is missing (`libhev-socks5-tunnel.so`, `libhev_fromstr_jni.so`). `fromStrReady` is false, `initError()` exposes the cause. Callers (`HevSocks5TunForwarder`, `OnionmasqTunForwarder`) check `isFromStrAvailable()` and throw `TunnelFailure.ForwarderDead` instead of silent no-op that would blackhole traffic.

- **kotlin-tor unix socket brick fixed**: `KotlinTorTorrc.kt` no longer publishes `appsSocksUnixPath` (kotlin-tor is TCP-only on `127.0.0.1:torSocksPort`). Previously this pointed to a non-existent unix file → `TorReadiness` / `SocksUidBridge` dialed a socket that never exists while traffic was on TCP port — hard brick.

- **LocalSocket readiness probe**: `TorReadiness.assertUnixSocksReady` now calls `connect()` **before** `setSoTimeout()`. Android `LocalSocket` throws "socket not created" if socket options are set on an unbound FD (W5-unix). Same order as `Socks5Client.openUnix`.

- **hev FromStr only (no password on disk)**: both forwarders removed the YAML path fallback (`HevConfigMaterializer.materialize()` writing password to cache dir). Only `TProxyStartServiceFromStr(config, fd)` (dlsym → `hev_socks5_tunnel_main_from_str`) is supported. On `rc != 0` or missing shim: hard fail with explicit message — no silent fallback.

- **/proc UID resolver budget**: `ConnectionOwnerResolver.MAX_PROC_LINES = 2048` applied to all four scan paths (`/proc/net/tcp`, `/proc/net/udp`, `/proc/net/tcp6`, `/proc/net/udp6`). Prevents DoS on pathological OEM stacks (massive `/proc/net` tables) and Waydroid.

- **TunDnsMux RFC1918 UDP reject with ICMP**: all four verdicts (`DENY`, `ALLOW_OVPN`, `ALLOW_LAN`, `ALLOW_TOR`) on LAN-destined UDP now emit ICMP port-unreachable (was silent drop for `DENY`/`ALLOW_LAN`/`ALLOW_TOR`). This makes Cake Wallet / Monero RPC retry Via LAN promptly instead of waiting for app-layer timeout (B04, M4). New helper `isUdp(buf, n)`.

- **ConnectionOwnerResolver SecurityException fallback**: API 29+ `getConnectionOwnerUid` can throw `SecurityException` ("VPN not active owner") during Blocking↔Connected transitions on some OEMs. Now caught, logged, and falls through to `/proc` fallback (same as Waydroid path) — previously aborted the whole lookup.

- **HevTProxyGate ownership serialization**: pre-Start `TProxyStopService()` when no prior owner cleans orphan native workers (crash/partial stop left TProxy running). Start/Stop guarded by token equality; second Start against live worker returns error instead of silent no-op.
