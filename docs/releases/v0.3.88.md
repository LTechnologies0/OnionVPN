## Highlights

Interactive firewall **Via LAN** for RFC1918 destinations (e.g. Cake Wallet → local Monero node on `192.168.x.x`).

## Firewall / LAN

- New verdict `ALLOW_LAN`: clearnet dial binds the LAN uplink `Network` first, then `VpnService.protect` (Wi‑Fi/Ethernet/USB) — not Tor or SoftEther.
- When the interactive firewall is on, IPv4 TCP to `10/8`, `172.16/12`, `192.168/16` prompts with **Via LAN** / **Deny** only (notification + full prompt).
- Tor exits and OpenVPN-over-Tor cannot reach the user’s LAN — those answers are refused for private destinations.
- CGNAT, loopback, VpnTun, and documentation addresses stay hard-blackholed.
- With the firewall off, private LAN stays fail-closed (silent blackhole).

## Also in this train (unreleased since 0.3.84)

- Optional kotlin-tor / kotlin-DNSCrypt backends (experimental engine options; not Tor Browser–grade anonymity).

## Install

- Phones: use **`onionvpn-0.3.88-arm64-v8a.apk`** only.
- Obtainium APK filter: `arm64-v8a`.
- Verify: `sha256sum -c SHA256SUMS.txt`.

## Build

- kotlin-tor / kotlin-DNSCrypt are optional composite includes (stubbed in CI when siblings are absent).

## Fixes

- Via LAN: Cake sibling exact-port rules (`18080/18081/18089`), sibling prompt cancel, longer UID wait, bind-then-protect dial retry — stabilizes Cake Wallet → local monerod without opening all TCP on that host.
